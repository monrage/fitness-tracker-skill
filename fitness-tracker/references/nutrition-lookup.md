# Nutrition lookup — каскад определения макросов

Перед каждым вызовом `log-food` ассистент проходит каскад снизу вверх и останавливается на первом сработавшем шаге.

---

## (a) Пользователь сам дал цифры → `source=manual`

Если пользователь явно назвал ккал / белок / жир / углеводы — брать их как есть.  
Уточнить грамовку, если не указана (см. *Порции* ниже).  
Сразу переходить к `log-food` с `--source manual`.

---

## (b) Брендовый / упакованный продукт или штрихкод → `lookup`, `source=off`

Используй CLI для запроса в Open Food Facts.

**По штрихкоду (точное совпадение):**
```
python scripts/fittrack.py lookup --barcode 3017620422003 --grams 30
```

**По названию (поиск, до 5 кандидатов):**
```
python scripts/fittrack.py lookup --query "молоко простоквашино" --grams 250
```

**Флаги `lookup`:**
| Флаг | Тип | Назначение |
|---|---|---|
| `--barcode` | строка | штрихкод EAN/UPC |
| `--query` | строка | свободный текст |
| `--grams` | float | желаемая порция в граммах |
| `--limit` | int (default 5) | макс. кандидатов для `--query` |

### Структура ответа

```json
{
  "results": [
    {
      "item": "Молоко Простоквашино 3,2%",
      "barcode": "4601662000023",
      "per100g": { "kcal": 60, "protein_g": 2.9, "fat_g": 3.2, "carbs_g": 4.7 },
      "scaled":  { "kcal": 150, "protein_g": 7.2, "fat_g": 8.0, "carbs_g": 11.8 },
      "grams": 250,
      "source": "off"
    }
  ],
  "count": 1
}
```

- `per100g` — всегда на 100 г; это основная модель хранения OFF.
- `scaled` — появляется только если передан `--grams`; вычисляется как `value_per100g × grams / 100`.
- Для `--query` может вернуть несколько кандидатов. Выбирай тот, чьё `item` ближе всего к тому, что назвал пользователь (совпадение бренда, жирности, формата). Уточни выбор вслух: *«нашёл Молоко Простоквашино 3,2% — это оно?»*
- Если `count: 0` — OFF не знает продукта; переходи к шагу (c) или (d).

**`off_country` в конфиге** (`nutrition.off_country`, например `"ru"`) направляет запросы на региональный зеркальный сервер OFF и улучшает попадания по локальным брендам.

После выбора кандидата: `--source off`.

---

## (c) Фото этикетки → ассистент читает сам, `source=label`

Если пользователь прислал фото упаковки с таблицей БЖУ:

1. Прочитай значения **на 100 г** прямо с изображения (vision).
2. Умножь на количество граммов порции:

```
kcal    = kcal_per_100g    × grams / 100
protein = protein_per_100g × grams / 100
fat     = fat_per_100g     × grams / 100
carbs   = carbs_per_100g   × grams / 100
```

**Пример.** Этикетка творога «Агуша»: 100 г → 101 ккал, Б 11 г, Ж 4 г, У 6,2 г.  
Порция 180 г:
```
kcal    = 101 × 180 / 100 = 181,8 → 182 ккал
protein = 11  × 180 / 100 = 19,8 г
fat     = 4   × 180 / 100 = 7,2 г
carbs   = 6,2 × 180 / 100 = 11,2 г
```

Используй `--source label`. Не запускай `lookup` — этикетка точнее базы.

---

## (d) Цельные продукты / домашние блюда → оценка ассистента, `source=claude`

Когда штрихкода нет и этикетки нет: оценивай из своей базы знаний по питанию.

- **Цельный продукт** (куриная грудка, греча, яйцо): напрямую вычисли макросы по граммам.
- **Составное блюдо** (борщ, плов, котлета): суммируй макросы ингредиентов по их весу, учитывай потери воды при приготовлении.

**Обязательно:** перед логированием озвучь оценку пользователю и получи подтверждение:  
*«Оцениваю 200 г куриной грудки (варёной): ~220 ккал, Б 41 г, Ж 5 г, У 0 г — записать?»*

Используй `--source claude`.

---

## Порции — перевод в граммы

Всегда называй допущение вслух.

| Мера | Типичный вес | Примечание |
|---|---|---|
| столовая ложка (масло/сметана) | ~15 г | для сыпучих ~20–25 г |
| чайная ложка | ~5 г | |
| стакан (жидкость) | ~200–250 мл | уточни объём |
| стакан (крупа сухая) | ~200 г | |
| штука — яйцо C1 | ~60 г | |
| штука — банан | ~120 г (без кожуры) | |
| порция (ресторан/кафе) | ~200–350 г | уточни или спроси |

Если пользователь говорит «тарелка борща» — уточни объём или используй 350–400 мл как разумный дефолт, явно указав допущение.

## Финальный вызов `log-food`

После того как макросы определены (любым шагом каскада):

```
python scripts/fittrack.py log-food \
  --date 2026-06-07 \
  --item "творог Агуша 5%" \
  --kcal 182 --protein 19.8 --fat 7.2 --carbs 11.2 \
  --meal breakfast --qty-g 180 \
  --source label
```

**Флаги `log-food`:**
| Флаг | Обязателен | Значение |
|---|---|---|
| `--date` | да | ISO `YYYY-MM-DD` |
| `--item` | да | название продукта/блюда |
| `--kcal` | да | калории |
| `--protein` | да | белок, г |
| `--fat` | да | жир, г |
| `--carbs` | да | углеводы, г |
| `--meal` | нет (default `snack`) | `breakfast` / `lunch` / `dinner` / `snack` |
| `--qty-g` | нет | вес порции в граммах |
| `--source` | нет (default `manual`) | `claude` / `off` / `label` / `manual` |
| `--notes` | нет | свободный текст |

### Ответ CLI

Ответ содержит `day` — текущие суточные итоги vs цели. Всегда транслируй их пользователю:  
*«Записал. После завтрака: 182 / 2 200 ккал, белок 19,8 / 165 г.»*
