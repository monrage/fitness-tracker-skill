# Обработка дат

## Главное правило

Определи **сегодняшнюю дату из контекста разговора** и передавай её как `--today YYYY-MM-DD` в каждую команду CLI. Никогда не полагайся на системные часы CLI — скрипт выполняется на стороне ассистента, а не пользователя.

**Логирование всегда ретроспективно.** "В понедельник жал 80 кг" = запись на прошедший понедельник.

- Дата не упомянута → сегодня.
- Голое название дня недели → самое недавнее прошедшее вхождение (сегодня считается).

---

## Поддерживаемые форматы (dates.py)

| форма | примеры |
|---|---|
| ISO | `2026-06-07` |
| Относительные (RU) | `сегодня`, `вчера`, `позавчера`, `завтра`, `послезавтра` |
| Относительные (EN) | `today`, `yesterday`, `day before yesterday`, `tomorrow` |
| N дней назад | `3 дня назад`, `3 days ago` |
| Неделю назад | `неделю назад`, `a week ago` |
| DD.MM или DD/MM | `05.06`, `5/6` |
| DD.MM.YYYY | `05.06.2026` |
| D месяца (RU) | `5 июня`, `3 марта` (включая родительный падеж) |
| month D (EN) | `june 5`, `march 3` |
| День недели RU | `понедельник` / `пн`, `вторник` / `вт`, `среда` / `ср` / `среду`, `четверг` / `чт`, `пятница` / `пт` / `пятницу`, `суббота` / `сб` / `субботу`, `воскресенье` / `вс` |
| День недели EN | `monday` / `mon`, `tuesday` / `tue`, `wednesday` / `wed`, `thursday` / `thu`, `friday` / `fri`, `saturday` / `sat`, `sunday` / `sun` |

Месяцы поддерживаются на RU (именительный и родительный: `июнь` / `июня`) и EN (`june` / `jun`).

## Разрешение через CLI

Для любой нестандартной фразы используй:

```
python scripts/fittrack.py resolve-date --text "в пятницу" --today 2026-06-07
```

Вывод:

```json
{
  "input": "в пятницу",
  "date": "2026-06-05"
}
```

Используй полученный `date` в дальнейших командах (`--date`).

## Таблица примеров (today = 2026-06-07, воскресенье)

| ввод пользователя | разрешённая дата | пояснение |
|---|---|---|
| `сегодня` | 2026-06-07 | today offset 0 |
| `вчера` | 2026-06-06 | offset −1 |
| `позавчера` | 2026-06-05 | offset −2 |
| `3 дня назад` | 2026-06-04 | offset −3 |
| `неделю назад` | 2026-05-31 | offset −7 |
| `5 июня` | 2026-06-05 | D месяца, текущий год |
| `05.06` | 2026-06-05 | DD.MM, текущий год |
| `в понедельник` | 2026-06-01 | последний пн до/включая сегодня |
| `в пятницу` | 2026-06-05 | последняя пт |
| `в субботу` | 2026-06-06 | последняя сб |
| `воскресенье` | 2026-06-07 | сегодня воскресенье → сегодня |
| `во вторник` | 2026-06-02 | последний вт |

## Неоднозначность — всегда отражай

Если дата неочевидна из контекста (фраза типа "в пятницу" без указания "прошлую" / "эту"), **повтори разрешённую дату** перед записью:

> Записал на пятницу, 5 июня — верно?

Дожидайся подтверждения, прежде чем вызывать `log-food` / `log-workout` / `log-weight`.

Особый случай: если пользователь говорит "на следующей неделе" — уточни, это не поддерживается как будущее в контексте логирования.

## Границы периодов

| команда | логика |
|---|---|
| `--period week` | Начало недели из `config.week_start` (`mon` или `sun`). Границы: `week_bounds(today, week_start)`. |
| `--period month` | Календарный месяц: 1-е число → последний день. |
| `--period year` | Календарный год: 1 января → 31 декабря. |
| `--period custom` | Требует `--date-from` и `--date-to` (оба ISO). |

Для `week` / `month` / `year` передавай только `--today`; CLI вычислит границы сам.
