# fitness-tracker — Claude Skill

Личный трекер питания и тренировок прямо в чате. Ассистент записывает еду с КБЖУ,
тренировки и вес тела, держит их против ваших целей и собирает сводки за неделю /
месяц / год. Данные хранятся в **вашем собственном** Notion, Google Sheets или
локальном файле — вы выбираете при первой настройке.

## Что умеет

- **Еда + КБЖУ** — пишете обычным языком («на обед 200 г куриной грудки и рис»),
  ассистент сам считает калории/белки/жиры/углеводы. Источники: знания Claude,
  Open Food Facts (по штрихкоду/названию, бесплатно), **фото этикетки** (Claude
  читает таблицу БЖУ) или ручной ввод.
- **Тренировки** — упражнения, подходы×повторы×вес (объём считается сам), кардио,
  длительность; статистика и личные рекорды (PR).
- **Вес тела** — динамика и тренд к цели.
- **Цели** — заданные напрямую или рассчитанные из антропометрии (Mifflin-St Jeor).
- **Даты** — понимает «вчера», «в понедельник», «5 июня», `05.06`, ISO; раскладывает
  записи по нужным числам (RU + EN).
- **Сводки** — день / неделя / месяц / год: приверженность, серии, PR, тренд веса.
- **Проактивный коучинг** — ненавязчивые подсказки по белку, частоте тренировок, плато.

## Требования

- **claude.ai** (web/desktop) с поддержкой Skills и исполнения кода.
- Python в песочнице — используется **только stdlib** (никаких `pip install`).

## Установка

1. Загрузите папку `fitness-tracker/` как Skill на claude.ai (Settings →
   Capabilities → Skills, либо как Project skill).
2. **Рекомендуется** завести отдельный **Claude Project** для трекера: в нём будут
   персистентно жить `fitness-config.json` (и `fitness-data.json` при локальном
   бэкенде) как файлы Project knowledge.
3. Напишите ассистенту что-нибудь вроде «хочу начать вести КБЖУ и тренировки» —
   он проведёт через настройку (`references/onboarding.md`).

## Хранилище данных

| Бэкенд | Настройка | Гайд |
|---|---|---|
| **Notion** (рекомендуется) | вставить integration token | `references/backends/notion.md` |
| **Google Sheets** (advanced) | одноразовый OAuth (refresh-token) | `references/backends/google-sheets.md` |
| **Local file** | без настройки (но нужен ручной export) | `references/backends/local.md` |

## Персистентность и приватность

Скилл **stateless** между сессиями — долговечность даёт хранилище:
- `fitness-config.json` (настройки, цели, **секреты**, указатель на бэкенд) —
  локальный файл; держите его файлом Project knowledge.
- Notion/Sheets хранят записи в **вашем** аккаунте; для восстановления доступа
  достаточно конфига. Локальный бэкенд требует сохранять и `fitness-data.json`.
- Токены/секреты не покидают ваш конфиг; ассистент шлёт их только в ваш бэкенд.

## Архитектура

```
SKILL.md          — роутер: триггеринг, онбординг-гейт, маршрутизация интентов
references/        — документация, грузится по необходимости (progressive disclosure)
  backends/        — пошаговая настройка Notion / Sheets / local
scripts/           — Python (stdlib): CLI fittrack.py + библиотеки логики/бэкендов
assets/            — пример конфига, Notion-схема, CSV-шаблон таблицы
evals/             — тест-промпты
```

Разделение труда: **ассистент** понимает язык, оценивает макросы, читает фото;
**`scripts/fittrack.py`** (CLI) детерминированно хранит данные, считает даты, ходит
в Open Food Facts, считает цели и агрегирует сводки, печатая JSON.

## Разработка и тесты (для мейнтейнеров)

```
python tests/test_foundation.py        # даты, записи, локальный бэкенд, конфиг
python tests/test_logic.py             # цели (Mifflin-St Jeor), сводки, масштабирование
python tests/test_backends_mapping.py  # маппинг Notion/Sheets (офлайн)
python tests/test_docs_consistency.py  # docs/assets ↔ контракты кода
python tests/test_off_live.py          # живой Open Food Facts (сеть; запускать в UTF-8)
```

Сетевые пути Notion и Google Sheets требуют **реальных учёток пользователя** —
их интеграционное тестирование выполняется на аккаунте конкретного пользователя
(чистая логика маппинга покрыта офлайн-тестами).
